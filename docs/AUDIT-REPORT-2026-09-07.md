# Архитектура и визуальная проверка Agatha Music

Дата: 7 сентября 2026. Проверка локального проекта и живого microsoft.ai через Chrome DevTools. Цель — улучшить существующий интерфейс без нового маркетингового контента, WebGL и интерактивного hero.

## Область и источники

- Chrome: главная Agatha, Classes, About, Media и Book; desktop 1440×1000, mobile 390×844, проблемные границы 768 и 861 px. Проверены снимки, DOM, computed styles, меню, hover, Escape, поля формы и реальный календарь.
- [Microsoft AI](https://microsoft.ai/) и [Models](https://microsoft.ai/models/) просмотрены в Chrome на desktop/mobile. Сопоставлены типографика, поверхности, меню, кнопки и CSS переходов.
- Локальные спецификации `docs/superpowers/specs/2026-08-10-reference-ui-parity-design.md`, responsive typography, spacing и актуальные тесты учитывались как история согласованной адаптации.
- Свежая production-сборка запущена на http://127.0.0.1:3000. Секреты, тексты, аккаунты, deployment и зависимости не изменялись. Публикации и отправки писем нет.

## Архитектура

Архитектура соразмерна сайту преподавателя. Основные страницы предварительно генерируются, `/book` рендерится на сервере, два API endpoint обслуживают контакт и webhook. Контент отделён в `content/`; клиентские компоненты обслуживают меню, вкладки, форму, видеопревью и embed. Собственного календаря, БД, CMS или auth нет.

Общая шкала CSS и готовые компоненты переиспользуются. Основная слабость визуального слоя — смесь масштабируемых токенов с фиксированными размерами и исключениями для отдельных страниц. На промежуточных ширинах это давало реальные ошибки сетки. Переписывать архитектуру для их устранения не требуется.

## Открытые вопросы и ограничения

1. **Версии окружения — исправлено после аудита:** первоначальная проверка выполнялась на Next 16.2.10 при manifest/lockfile 16.3.0. По подтверждению пользователя выполнен `npm.cmd ci --no-audit --no-fund`. Next, eslint-config-next, @next/env и @next/eslint-plugin-next теперь 16.3.0, без ошибки `invalid`. Manifest и lockfile не изменились. На 16.3.0 повторно прошли `npm.cmd run check` (typecheck, lint, 93 unit-теста, production build) и полный `npm.cmd run e2e:run` (42 passed, 1 штатно skipped). Локальная production-сборка перезапущена на порту 3000; мобильная главная дополнительно просмотрена в Chrome.
2. **Footer touch targets:** Lighthouse отмечает высоту ссылок 19.2 px вместо 24 px. Сохранён ранее согласованный плотный line-height ритм; это открытый компромисс, не исправленный в текущем проходе.
3. **Документация устарела:** AGENTS/launch checklist требуют 404 для `/en`, но более поздняя спецификация, код и тесты задают пять точных English redirects. Контракты маршрутов сохранены. Checklist также содержит удалённые audience URLs. AGENTS не редактировался.
4. **Готовность к запуску:** в проекте остаются legal placeholders и незакрытые пункты launch checklist. Реальные реквизиты, Resend sender, Cal.com account settings и production env не проверялись и не изменялись.
5. **Локальные console errors:** `/_vercel/insights/script.js` и `/_vercel/speed-insights/script.js` возвращают 404 на локальном `next start`. Вывод о состоянии этих endpoint в production не делался.
6. **Полное визуальное совпадение:** отсутствуют scroll reveals, актуальная grid-композиция Models и часть обновившихся элементов live reference. Ни процент pixel parity, ни полное соответствие не заявляются.
7. **Границы QA:** основной браузер Chromium/Chrome; Safari/Firefox и реальные устройства не проверены. Lighthouse проверил только одну страницу и состояние. Реальные письма и бронирования не отправлялись.
